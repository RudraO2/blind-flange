- source_spec: Story 1.4 (`conversation.hero.agentPreset` seat) — FIXED 29 Aug 2026
  summary: An intermittent boot failure — "Failed to load plugins: single slot conversation.hero.agentPreset already has a registration at priority 0 (registered by z5)" — hit `npm start`/`run.bat` on some boots and not others, on this machine and independently on a teammate's fresh clone of the same commit. Root cause found and fixed same day; kept here for the record rather than deleted, because the first write-up of this entry was itself wrong and that is worth being honest about.
  evidence: 29 Aug 2026. `ui-agent-preset` (`@deepseek-ai/dsh-client-ui-agent-preset`) registers into `conversation.hero.agentPreset` with no explicit `id` in its own source (`lib/client.js`, the `scope.slots.register({ name: "conversation.hero.agentPreset", locale: ..., inject: seatInjected }, AgentPresetSeat)` call) — the harness assigns an auto-generated id at registration time, which is what "z5" is, not a stable name. **This entry originally claimed `profile/web/cordis.patch.yml` already carried a `- id: ui-agent-preset\n  disabled: true` row and that it was correctly targeted — that was wrong.** The row never existed in this file, in any commit (`git log --all -S"ui-agent-preset"` finds none), so the two plugins were both active every boot, both registering into the same single-occupancy slot at the same default priority with no disable in place at all. Whichever activated first silently won the slot; the other threw the "already has a registration" error. Load order between an inserted row and the bundle's own shipped registration isn't guaranteed, which is exactly the intermittency observed — including this machine booting clean minutes after a failed boot, same commit, same config. Fixed by adding the missing `- id: ui-agent-preset\n  disabled: true` row to `profile/web/cordis.patch.yml` (same pattern as the `ui-brand-official` row just below it), which removes the race outright instead of winning it by luck. A teammate independently reached the same fix by testing.
